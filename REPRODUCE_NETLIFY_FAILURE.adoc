= Reproduce the failed Netlify build of docs.asciidoctor.org
:toc:

== Problem

The Netlify build of https://github.com/asciidoctor/docs.asciidoctor.org[docs.asciidoctor.org] failed.
The failed deploy is `6b026b6145e44c1569284511` of the `asciidoctor-docs` site.
We want to reproduce this failure on a local machine.

== Cause

The failure comes from broken symlinks in the `docs` folder of this repository.
It does not come from the playbook repository.

* The deploy ID is a hex timestamp.
It decodes to 2026-11-22 04:11 UTC.
* At that time, `main` was at commit `a1332cf2` ("Move fixtures to a separate asciidoctorj-fixtures module").
* The two next commits fix the problem:
** `0494affc` fix broken symlink
** `a657fe7e` fix broken symlinks
* At `a1332cf2`, three symlinks pointed to files in `asciidoctorj-documentation`.
The module renames and moves removed these files:
** `docs/modules/ROOT/examples/org/asciidoctor/integrationguide/PdfOptionsTest.java`
** `docs/modules/syntax-highlighting/examples/org/asciidoctor/integrationguide/syntaxhighlighter/PrismJsHighlighter.java`
** `docs/modules/syntax-highlighting/examples/org/asciidoctor/integrationguide/syntaxhighlighter/PrismJsHighlighterTest.java`

NOTE: We did not read the Netlify log.
The page needs a login.
The cause comes from the timeline and from the broken symlinks.
Step 4 of the plan checks the exact error text.

== Plan

. Prepare the Antora image.
Use the Docker image `antora/antora`.
Install `@asciidoctor/tabs` in a site folder that is mounted in the container.
Docker is the only tool you need on the host (and git).
. Prepare the source.
Clone this repository into a work folder.
Create the branch `repro-broken` at `a1332cf2`.
Create the branch `repro-fixed` at the fixed commit.
Antora reads committed content from git, so the commits must be on branches.
. Generate one playbook for each branch.
Each playbook has only the AsciidoctorJ source, `docs` as the start path, and `failure_level: warn`.
The UI bundle is the same as in the real playbook.
. Build the `repro-broken` branch.
Run `antora` in the Docker image with the options of the Netlify production command, without the Algolia extension.
Compare the log with the Netlify log.
The build must fail.
. Build the `repro-fixed` branch with the same command.
The build must pass.
This proves that the two commits fix the problem.

== Run the plan

The script `reproduce-netlify-failure.sh` does all the steps:

[source,shell]
----
./reproduce-netlify-failure.sh          # setup, broken build, fixed build, summary
./reproduce-netlify-failure.sh setup    # steps 1 to 3 only
./reproduce-netlify-failure.sh broken   # build the broken commit only
./reproduce-netlify-failure.sh fixed    # build the fixed commit only
./reproduce-netlify-failure.sh clean    # delete the work folder
----

The script does not change this repository or your local playbook checkout.
The container runs as your user and mounts only the work folder.
All files go to the work folder (default: `$TMPDIR/asciidoctorj-docs-repro`).
The logs are in `results/broken.log` and `results/fixed.log` in that folder.

You can change the behavior with environment variables:

[cols="1,2,2"]
|===
|Variable |Meaning |Default

|`BROKEN_REF`
|Commit with the broken symlinks
|`a1332cf2`

|`FIXED_REF`
|Commit with the fix
|`HEAD`

|`SOURCE_REPO`
|AsciidoctorJ repository to read
|folder of the script

|`ANTORA_IMAGE`
|Antora Docker image
|`docker.io/antora/antora:latest`

|`TABS_VERSION`
|Version of `@asciidoctor/tabs`
|`1.0.0-beta.6`

|`FAILURE_LEVEL`
|Antora log failure level
|`warn`

|`WORK_DIR`
|Folder for generated files
|`$TMPDIR/asciidoctorj-docs-repro`
|===

== Limits

* The script builds only AsciidoctorJ.
Warnings about links to other components (for example, xrefs) can fail both builds.
If this happens, compare the two logs.
Only the symlink messages must be different.
* The script uses its own minimal playbook, not the real `antora-playbook.yml`.
The Antora version is the one in the image, not the one in the lock file of the playbook repository.
* The script does not run the Netlify `checklinks` plugin.
This plugin runs after the build, so the failure does not need it.
* Changes that are not committed are not part of `FIXED_REF`.

== Follow-up

Add a check to the CI of this repository that fails when `find docs -xtype l` prints a result.
This check finds broken symlinks before Netlify does.
