== Renamed artifacts

AsciidoctorJ v4.0.0 has two implementations, the JRuby implementation and the Java implementation.
The artifacts of the JRuby implementation are renamed, so that the name tells which implementation is used:

[cols="1,1"]
|===
|3.x |4.0

|`org.asciidoctor:asciidoctorj`
|`org.asciidoctor:asciidoctorj-jruby`

|`org.asciidoctor:asciidoctorj-cli`
|`org.asciidoctor:asciidoctorj-jruby-cli`

|`org.asciidoctor:asciidoctorj:<version>:bin@zip` (distribution)
|`org.asciidoctor:asciidoctorj-jruby:<version>:bin@zip`
|===

`org.asciidoctor:asciidoctorj-api` is not renamed, since it's shared by both implementations.

Update the dependency:

[,xml]
----
<dependency>
  <groupId>org.asciidoctor</groupId>
  <artifactId>asciidoctorj-jruby</artifactId>
  <version>4.0.0</version>
</dependency>
----

`org.asciidoctor:asciidoctorj` is still published as a relocation to `org.asciidoctor:asciidoctorj-jruby`, so a build that depends on it keeps working.
Update the dependency anyway, since the relocation may be removed in a future version.

The distribution zip now expands into an `asciidoctorj-jruby-<version>` directory.
The command is still named `asciidoctorj`.

NOTE: If you want to run AsciidoctorJ without JRuby, see xref:migrate-to-java-implementation.adoc[], which uses `org.asciidoctor:asciidoctorj-java`.
