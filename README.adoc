{uri-repo}[AsciidoctorJ] is the official library for running {uri-asciidoctor}[Asciidoctor] on the JVM.
Using AsciidoctorJ, you can convert AsciiDoc content or analyze the structure of a parsed AsciiDoc document from Java and other JVM languages.

Since version 4.0, AsciidoctorJ is a pure Java implementation of Asciidoctor (Java 17 or newer, no runtime dependency): it doesn't run Asciidoctor (Ruby) on JRuby anymore.
The API is the API of AsciidoctorJ 3; see the xref:docs/migration-from-asciidoctorj.adoc[migration guide] for the differences.

You can find the documentation for integrating Asciidoctor in your JVM based language of choice at the {uri-docs}/asciidoctorj/latest/[Asciidoctor Docs site].

The command line interface is also available as native executables for Linux (amd64 and arm64), macOS (arm64) and Windows (amd64), which don't require a Java runtime, on the {uri-releases}[GitHub releases].

== Using the command line interface

Download the native executable for your platform from the {uri-releases}[GitHub releases] and extract it.
Verify that it runs (it displays the various run options available):

[source,shell]
----
asciidoctorj --help
----

Next, convert an AsciiDoc file, such as this README, to HTML:

[source,shell]
----
asciidoctorj README.adoc
----

The options are the options of the `asciidoctor` command (`asciidoctorj --help`), except:

* `-r` loads a Java class instead of a Ruby library: a registry (`ExtensionRegistry`, `ConverterRegistry` or `SyntaxHighlighterRegistry`, in the `org.asciidoctor.jruby.*.spi` packages), which is registered, a converter (annotated with `@ConverterFor`) or an extension (a processor, such as a `BlockProcessor` annotated with `@Name`); `-r` also accepts a jar, whose services (`META-INF/services`) are loaded;
* `-I` adds a directory or a jar to the class path, whose services (`META-INF/services`) are loaded and whose classes can be required with `-r`.

For instance, `asciidoctorj -r my-extensions.jar README.adoc` converts the document with the extensions that the jar registers as services.

The native executables can't load classes at runtime: `-I` and `-r FILE.jar` fail, and `-r` can only load the classes that the executable contains.
The command line interface can also be run with Java: `java -jar asciidoctorj-native-cli-{artifact-version}.jar`, with the jars of the implementation and of the API (`asciidoctorj-native-{artifact-version}.jar` and `asciidoctorj-api-{artifact-version}.jar`) in the same directory.

=== Windows installation

A {uri-chocolatey}[Chocolatey] package installs the native executable for Windows:

----
C:\> choco install asciidoctorj
C:\> asciidoctorj README.adoc
----

== Installation

To start using AsciidoctorJ, add the dependency to your build:

[source,xml]
[subs="specialcharacters,attributes"]
.Declaring the dependency in a Maven build file (i.e., pom.xml)
----
<dependencies>
  <dependency>
    <groupId>org.asciidoctor</groupId>
    <artifactId>asciidoctorj-native</artifactId>
    <version>{artifact-version}</version>
  </dependency>
</dependencies>
----

[source,groovy]
[subs="specialcharacters,attributes"]
.Declaring the dependency in a Gradle build file (e.g., build.gradle)
----
dependencies {
  implementation 'org.asciidoctor:asciidoctorj-native:{artifact-version}'
}
----

Then convert a document with the API:

[source,java]
----
import java.io.File;

import org.asciidoctor.Asciidoctor;
import org.asciidoctor.Options;
import org.asciidoctor.SafeMode;
import org.asciidoctor.ast.Document;

try (Asciidoctor asciidoctor = Asciidoctor.Factory.create()) {
    String html = asciidoctor.convert("Hello, *AsciiDoc*!", Options.builder()
        .safe(SafeMode.SAFE)
        .standalone(false)
        .build());

    Document doc = asciidoctor.loadFile(new File("README.adoc"), Options.builder().build());
    System.out.println(doc.getDoctitle());
}
----

[TIP]
====
In addition to using AsciidoctorJ directly, you can invoke it as part of your build using the Maven or Gradle plugin:

- {uri-docs}/maven-tools/latest/[Asciidoctor Maven Tools]
- {uri-docs}/gradle-plugin/latest/[Asciidoctor Gradle Plugin]

=== Features

* The AsciidoctorJ API: conversion, loading of documents and access to the AST (`Document`, `Section`, `Block`, `List`, `Table`, `PhraseNode`...)
* Converters: HTML 5, DocBook 5 and man page, and custom converters written in Java (including converters producing something else than a String)
* Extensions written in Java: preprocessor, tree processor, postprocessor, include processor, docinfo processor, block, block macro and inline macro processors
* Syntax highlighting with highlight.js and Prettify, and syntax highlighters written in Java
* Logging (`LogHandler`)

The features that rely on Ruby are not supported: Ruby extensions and libraries (gems, e.g., Asciidoctor PDF or Asciidoctor Diagram), the syntax highlighters that require a gem (Rouge, CodeRay, Pygments) and the converter templates (Tilt).

== Development

AsciidoctorJ is built with Gradle (using the Gradle Wrapper) and JDK 17 or newer.

[source,shell]
----
./gradlew build
----

Run a single test class:

[source,shell]
----
./gradlew :asciidoctorj-core:test --tests DocumentTest
----

=== Project layout

[horizontal]
`asciidoctorj-api`:: the API (`org.asciidoctor:asciidoctorj-api`)
`asciidoctorj-core`:: the implementation (`org.asciidoctor:asciidoctorj-native`): the port of Asciidoctor in `org.asciidoctor.core` (a flat package mirroring `lib/asciidoctor`, plus `converter`, `extension`, `syntaxhighlighter` and `log`), the implementation of the API in `org.asciidoctor.core.api`, the test suite of Asciidoctor translated to JUnit 5 (`org.asciidoctor.core`) and the tests of the API (`org.asciidoctor`)
`asciidoctorj-cli`:: the command line interface (`org.asciidoctor:asciidoctorj-native-cli`), and its tests (which use the test helpers and fixtures of `asciidoctorj-core`)
`asciidoctorj-test-support`:: JUnit 5 extensions to test AsciidoctorJ and its extensions (e.g., inject an `Asciidoctor` instance or a classpath resource)
`asciidoctorj-documentation`:: the tests that back the code snippets of the documentation
`asciidoctorj-springboot-integration-test`:: checks that AsciidoctorJ works in a Spring Boot executable jar (nested jars)
`chocolatey`:: the Chocolatey package, which installs the native executable for Windows
`docs`:: the documentation (Antora), the migration guide, the notes about the API and the status of the port
`tools`:: the scripts used to translate the tests of Asciidoctor (`rb2java.rb`, `fix_tests.py`, `regen.sh`), to compare the output with Asciidoctor (`compare`) and to build and test the native executable (`build-native.sh`, `native-smoke-test`)

=== Following Asciidoctor

The implementation is a port of {uri-asciidoctor-repo}[Asciidoctor] that follows the Ruby source file by file (one Java class per Ruby class, same method order), so that the changes made to Asciidoctor can be ported easily.
It follows the main branch of Asciidoctor (commit `52871a02`).
The test translation tools expect Asciidoctor to be checked out next to this project (`../asciidoctor`).
The status of the port and the improvement backlog are tracked in xref:docs/port-status.adoc[].

=== Native executable

The command line interface can be compiled to a native executable with {uri-graalvm}[GraalVM] (JDK 25):

[source,shell]
----
./gradlew :asciidoctorj-cli:assemble
tools/build-native.sh
./asciidoctorj-cli/build/native/asciidoctorj -o - README.adoc
----

The jars contain the native image configuration (`META-INF/native-image`), so the library can also be embedded in another native application.
`tools/native-smoke-test/run.sh` verifies the native executable (and compares its output with the output of the JVM when the jar is specified).

=== Continuous integration

The project is built and tested on Linux, macOS and Windows with Java 17, and on Linux with Java 25, and the native executables are built and tested on each platform, by GitHub Actions (`.github/workflows/ci.yml`).
