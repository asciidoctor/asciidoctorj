= Contributing

== Commit messages

Commit messages follow the https://www.conventionalcommits.org/en/v1.0.0/[Conventional Commits] specification:

----
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
----

The description is written in the imperative mood, in lowercase, without a trailing period (e.g., `fix: escape the ampersand in link text`).

Types:

[horizontal]
`feat`:: a new feature (or an upstream feature ported from Asciidoctor)
`fix`:: a bug fix
`docs`:: documentation only
`test`:: adding or fixing tests (including the test translation tools)
`refactor`:: a code change that neither fixes a bug nor adds a feature
`perf`:: a performance improvement
`style`:: formatting, no change of behavior
`build`:: build system or dependencies (`*.gradle`, `gradle/libs.versions.toml`)
`ci`:: continuous integration (`.github/workflows`)
`chore`:: other changes (repository configuration, etc.)

The scope is optional and names the affected area, e.g., `converter`, `extension`, `cli`, `parser`, `logger`.
A breaking change is marked with `!` after the type or scope (e.g., `feat(api)!: ...`) and described in a `BREAKING CHANGE:` footer.

When a commit ports an upstream change, reference the Asciidoctor commit or issue in the body (e.g., `Port of asciidoctor/asciidoctor@29837383`).
