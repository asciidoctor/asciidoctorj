This document provides a high-level view of the changes introduced in the native implementation of AsciidoctorJ by release.
The changes of the JRuby implementation and of the API are listed in link:../CHANGELOG.adoc[].
For a detailed view of what has changed, refer to the {url-repo}/commits/main[commit history] on GitHub.

== Unreleased

The native implementation of AsciidoctorJ (`org.asciidoctor:asciidoctorj-native`) is a pure Java implementation of Asciidoctor: it doesn't run Asciidoctor (Ruby) on JRuby.
It implements the same API as the JRuby implementation (`org.asciidoctor:asciidoctorj`); see the migration guide (asciidoctorj-native/docs/migration-from-asciidoctorj.adoc) for the differences.

Differences with the JRuby implementation::

* Java 17 is the minimum supported version
* Ruby extensions and Ruby libraries (gems) are not supported (`Asciidoctor#rubyExtensionRegistry()`, `Asciidoctor#requireLibrary`), as well as the syntax highlighters that require a gem (Rouge, CodeRay, Pygments) and the converter templates (Tilt)
* The JRuby specific classes (`AsciidoctorJRuby`, `JRubyAsciidoctor`) are not available
* The `-r` option of the command line interface loads a Java class (an `ExtensionRegistry`, `ConverterRegistry` or `SyntaxHighlighterRegistry`, a converter or an extension) or a jar whose services are loaded (instead of a Ruby library); the services of the directories and jars added with `-I` are loaded
* No distribution (zip, tar): the command line interface is available as native executables (Linux, macOS, Windows) published on the GitHub release
* No Arquillian extension (`asciidoctorj-arquillian-extension`)

Improvements::

* Pure Java implementation of Asciidoctor (port of Asciidoctor 2.0.x, main branch), with no runtime dependency
* The command line interface has no dependency (JCommander is not used anymore) and is available as native executables (GraalVM)
* The Chocolatey package installs the native executable for Windows (no Java runtime required)
